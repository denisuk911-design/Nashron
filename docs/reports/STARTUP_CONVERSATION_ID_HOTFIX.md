# Startup / conversation_id hotfix

## Scope

This report covers the critical startup regression in which the packaged application could fail before the chat window opened with:

```text
AttributeError: 'MainWindow' object has no attribute 'conversation_id'
```

No provider, routing, skills, or runtime behavior was redesigned in this hotfix.

## Reproduction and diagnosis

The first reproduction was run against the exact main artifact:

```text
dist/Roman 2050/Roman 2050.exe
```

The pre-fix process stayed alive during the short smoke, but source inspection exposed the deterministic lifecycle defect. `UniversalPlatformService` was constructed with `self.conversation_id` before `MainWindow.__init__` assigned it with `ensure_single_conversation()`.

The short process-alive check also exposed a second startup weakness: synchronous Codex version/login checks and rendering the entire accumulated conversation delayed the interactive window. Both were addressed because a live process is not proof that `MainWindow` is ready.

## Fix

`MainWindow` now establishes explicit baseline state at the beginning of construction:

- `conversation_id = None`
- `active_organization_id = None`
- `current_thread_id = None`
- `current_task_id = None`

After database initialization, the constructor resolves and validates the conversation before constructing any dependent service. It then resolves the active organization. Startup transitions are logged in order:

```text
APP_START
SETTINGS_READY
DATABASE_READY
MANAGEMENT_READY
CONVERSATION_RESOLVED
ORGANIZATION_RESOLVED
CHAT_SERVICES_READY
MAINWINDOW_READY
USER_INTERACTIVE
```

Management foundations are completed before conversation and organization resolution. Provider availability is checked without launching blocking CLI commands during construction. Detailed version/authentication checks remain on the existing provider interaction paths. Initial chat restoration uses the configured `history_message_limit` so a large history cannot prevent the main window from becoming interactive.

The code does not use `getattr` to hide a missing `conversation_id`.

## Verification

- Full test suite: `223 passed`.
- True Qt bootstrap test constructs `MainWindow` through its normal constructor and verifies that dependent services receive the same resolved conversation.
- The bootstrap test covers clean first run, existing conversation data, and existing active organization data.
- Windows build completed with `scripts/build_windows.bat`.
- The packaged main EXE was launched from `dist/Roman 2050/Roman 2050.exe`.
- After 15 seconds, the visible main window title was `Отдел важных дел` and startup logs reached `MAINWINDOW_READY` and `USER_INTERACTIVE`.
- A real message entered through the packaged window was persisted to SQLite; the process remained alive after submission.
- The smoke message was removed after verification.

The packaged footer and About dialog now expose version, source commit, and UTC build timestamp through `build_info.json` generated by the Windows build script.
