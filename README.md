# Roman 2050

Roman 2050 - настольное приложение для Windows 10/11, в котором пользователь общается с персонажем Романом Неслышевым в одном постоянном разговоре. Интерфейс выполнен как тёмный desktop-мессенджер с отдельными карточками сообщений, боковыми панелями и изолированной рабочей папкой. История общения, настройки и пользовательская память хранятся локально. Генерация ответов выполняется через установленный Codex CLI и требует интернет-соединения и авторизации ChatGPT в Codex CLI.

## Требования

- Windows 10 или Windows 11.
- Python 3.12 или новее.
- Codex CLI в `PATH` или встроенный `vendor\codex\win-x64\codex.exe`.
- Gemini CLI в `PATH` для второго собеседника Петра Перрова.
- Переменная окружения `GEMINI_API_KEY` для авторизации Gemini CLI.
- Доступ к интернету для генерации ответов через Codex и Gemini.

## Установка Python

Скачайте Python с официального сайта python.org. В установщике включите пункт `Add python.exe to PATH`.

Проверка:

```bat
python --version
```

## Установка Codex CLI

В текущей сборке рядом с приложением поставляется `vendor\codex\win-x64\codex.exe`, если этот файл был найден при сборке. Поэтому запуск из Проводника не требует ручной установки Codex CLI в `PATH`.

Если встроенного файла нет, приложение дополнительно ищет `codex` в `PATH` и в типовой папке расширения VS Code OpenAI ChatGPT:

```text
%USERPROFILE%\.vscode\extensions\openai.chatgpt-*\bin\windows-x86_64\codex.exe
```

Приложение не запрашивает пароль ChatGPT и не читает токены.

Проверка:

```bat
codex --version
codex login status
```

## Запуск

Из каталога проекта:

```bat
scripts\run_windows.bat
```

Скрипт создает `.venv`, устанавливает зависимости и запускает `app.py`.

## Вход через ChatGPT

В приложении нажмите `Войти через ChatGPT`. Будет запущена официальная команда встроенного или найденного Codex CLI:

```bat
codex login
```

Roman 2050 не показывает собственную форму пароля, не читает токены и не сохраняет авторизационные данные.

## Выход

Кнопка `Выйти` запускает:

```bat
codex logout
```

## Командный режим с Петром

В приложении есть два рабочих собеседника:

- Роман Неслышев - работает через Codex CLI.
- Петр Перров - работает через Gemini CLI.

Если пользователь пишет `Роман, ...`, отвечает Роман. Если пишет `Петр, ...`, `Пётр, ...` или `Gemini, ...`, отвечает Петр. Если в сообщении названы оба, отвечают оба по очереди. Если задача не назначена явно, приложение вызывает обоих: они кратко обсуждают план, объективно уточняют слабые места и решают, кто выполняет работу.

Ответы обоих агентов намеренно ограничены по стилю: коротко, по сути, без длинных справок и без автоматического согласия друг с другом.

## Данные, база и логи

Пользовательские данные находятся в:

```text
%LOCALAPPDATA%\Roman2050
```

Там создаются:

- `roman2050.sqlite3` - SQLite-база одного постоянного разговора, полной истории сообщений и воспоминаний. Если в старой версии было несколько диалогов, при запуске они автоматически объединяются в один разговор, а рядом создается резервная копия `roman2050.before_single_dialog.sqlite3`.
- `data\roman_identity.json` - пользовательская копия канона личности.
- `data\roman_identity.initial.bak.json` - резервная копия начального канона.
- `logs\roman2050.log` - технический журнал без паролей, токенов и полного текста разговора.
- `GEMINI_API_KEY` хранится как пользовательская переменная окружения Windows, а не в исходниках проекта и не в шаблонах настроек.
- `workspace_root` в настройках - изолированная рабочая папка по умолчанию `%USERPROFILE%\Documents\Roman2050 Workspace`. В ней создаются `Imports`, `Projects`, `Images`, `Documents`, `Code`, `Exports`, `Temp` и служебные runtime-каталоги.

Исходные шаблоны лежат в `data` и `prompts` внутри проекта и копируются при первом запуске.

## Локальный помощник

В настройках есть флажок `Разрешить Codex читать/создавать файлы и выполнять команды`. Когда он выключен, Codex запускается с `--sandbox read-only` и используется как текстовый движок. Когда он включен, Codex запускается с `--sandbox danger-full-access`, поэтому может читать и создавать файлы и выполнять команды на компьютере в рамках возможностей Codex CLI.

Включайте этот режим только когда действительно хотите дать помощнику доступ к компьютеру. Приложение журналирует факт включения режима, но не записывает секреты и полные сообщения в технический лог.

Внешние вложения сначала копируются в `workspace_root\Imports`. `PathGuard` запрещает абсолютные пути, переходы через `..`, UNC-пути, NTFS alternate data streams и выход за пределы workspace. Codex запускается из `workspace_root\.runtime\chat`, а не из каталога исходников приложения.

## Восстановление личности

Если `roman_identity.json` поврежден, чат блокируется. Замените файл в `%LOCALAPPDATA%\Roman2050\data\roman_identity.json` копией `%LOCALAPPDATA%\Roman2050\data\roman_identity.initial.bak.json` или исходным шаблоном из `data\roman_identity.json`.

## Тесты

```bat
.venv\Scripts\python.exe -m pytest
```

Тесты проверяют загрузку и повреждение канона, неверное имя и год, построение системного контекста, сохранение полной истории, SQLite, отсутствующий Codex CLI, тайм-аут, ненулевой код возврата, отмену процесса и переключение режима полного доступа.

## Сборка EXE

```bat
scripts\build_windows.bat
```

Сборка выполняется через PyInstaller. В EXE включаются `prompts\roman_system.md`, `data\roman_identity.json`, `data\roman_timeline.json`, `data\app_settings.json` и, если есть, `vendor\codex\win-x64\codex.exe`. Пользовательские данные все равно хранятся в `%LOCALAPPDATA%\Roman2050`, а не в `Program Files`.

## Архитектура

- `core/settings_service.py` - пути, копирование шаблонов, настройки.
- `core/database.py` - SQLite-таблицы `conversations`, `messages`, `user_memories`, `app_events`; `conversations` используется как внутренняя техническая таблица для одного постоянного разговора.
- `core/identity_service.py` - проверка канона, SHA-256, резервная копия.
- `core/prompt_builder.py` - сборка контекста из prompt, личности, timeline, памяти и полной истории диалога.
- `core/codex_client.py` - адаптер к Codex CLI через `subprocess`, без `shell=True`.
- `core/gemini_client.py` - адаптер к Gemini CLI через `subprocess`, `GEMINI_API_KEY` передается только через environment дочернего процесса.
- `core/agents.py` - описание рабочих агентов Романа и Петра.
- `core/workspace_service.py` и `core/path_guard.py` - создание workspace, копирование вложений и проверка границ путей.
- `gui/theme/` - токены, темы и ресурсы оформления.
- `gui/main_window.py` - трёхколоночное главное окно и сценарии интерфейса.
- `gui/worker.py` - фоновая генерация через `QThread`.
- `gui/chat/message_widget.py` - отдельная карточка каждого сообщения.

## Известные ограничения

- Автоматическое извлечение долговременной памяти и полноценный движок развития Романа пока не реализованы; пользователь сохраняет выбранные сообщения вручную.
- Полный файловый браузер, превью медиа, звуковая система и advanced-scroll controller из расширенного ТЗ пока находятся в следующем этапе.
- Формат вывода Codex CLI и Gemini CLI может меняться; клиенты ориентируются на код возврата и стабильные headless-режимы CLI.
- Качество ответов зависит от установленных версий Codex CLI и Gemini CLI, авторизации, ключа Gemini и доступности сети.
